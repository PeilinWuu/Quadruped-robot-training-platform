# 仿真相对热像展示

本轮保留已实现的 GS 深度遮挡和窗帘表面修正，仅增加独立热像面板。它不重跑仿真，不修改 V1/V2 火焰播放文件，不输出标定摄氏度或机器人训练真值。

## 使用与验收

1. 启动桌面应用，加载 `D:/interiorgs_data/office_01/scene_yup.sog`。
2. 选择 V1 火焰，开启房间火场模式。在传感器面板选择“仿真热像”。
3. 用桌子、沙发、窗帘视角检查热区与着火位置的对应关系；旋转相机检查前景家具遮挡热源。
4. 播放时热区随源帧变化；暂停时固定相机的结果应稳定，移动相机仍更新投影。
5. 检查铁红、白热、黑热色带和固定 0–1 色标。鼠标显示相对热度，不显示 °C。
6. 切换第一视角、调整窗口大小、多视图与单热像视图；卸载 GS 场景后不应保留旧热像。

开发启动：`npm run tauri -- dev`。数据路径配置见 [数据与资源](DATA_ASSETS.md)；已有 5173 服务时见 [故障排查](TROUBLESHOOTING.md)。本机临时配置不会随 Git 拉取。

## 数据和渲染

- 气体直接使用 V1 RG8 播放数据的 G 通道，按同一 current / next / alpha 插值，不从 RGB 亮度或燃料颜色反推温度。
- 固体来自现有仿真的 `wood_temperature/*.npz`，取与 V1 完全相同的 sourceFrame。按跨帧热区并集裁剪，保留原网格分辨率，除以模型上限 1.2 后量化为 uint8。
- 固体附加文件为每个 V1 场景下 `thermal.json` 和 `thermal_NNN.bin`。桌子 72 帧、沙发和窗帘各 16 帧，总计约 3.3 MB。附加导出不覆盖原 `metadata.json` 和火焰 chunks。
- 捕获 GS 深度时同时保存相机世界矩阵、投影矩阵与各场景的已发布播放样本。深度转相机前向距离后，在当前视线可见表面查询固体温度；沿表面之前的视线积分气体。
- 使用相对辐射近似 `heat^4` 和固定吸收系数 `3 * heat`，按前后顺序做发射 / 透射累积，再取四次方根显示。多个气体体积的贡献在同一射线步合并，不依赖场景列表顺序。
- 窗帘的气体遵循现有 0–20 cm 展示偏移；固体始终留在原表面坐标，不随该偏移移动。
- 背景无仿真温度，统一设为相对热度 0.08。无有效 GS 深度的像素显示灰蓝色，并屏蔽热源，避免将未知区域误画成可见高温。
- Worker 独立计算，192 像素宽、按视口比例取高度，最多 5 Hz；繁忙时跳过新请求，不积累帧队列。固体帧缓存最多 12 帧。关闭面板、卸载场景、上下文丢失时清理线程和结果。
- V2 没有原始温度通道，明确提示切回 V1。固体文件缺失或深度失败时显示错误，不以伪造画面替代。

## 重现导出和检查

```
python scripts/export-thermal-playback.py D:/interiorgs_data/office_01/fire_playback/table_high D:/interiorgs_data/office_01/fire_playback_room/sofa_high D:/interiorgs_data/office_01/fire_playback_room/curtain_high
npm run test:frontend
node scripts/verify-thermal.mjs
npm run tauri -- build
```

Vite 开发路由和 Tauri 生产资源白名单均包含温度附加文件；桌面打包前校验温度帧 SHA-256。GS 房间仍由用户本地导入，不打进安装包。

自动验收包括合成几何下前后遮挡、无深度屏蔽、固体表面采样、温度通道与帧插值、热源顺序一致性；真实 SOG 测试覆盖三处热源、播放、第一视角、缩放、色带、关闭和销毁。截图及报告写入 `tmp/thermal-results`。人工观感验收仍由用户完成。

## 当前边界

气体与固体是不同模型中的归一化场，统一色标只是展示约定。环境没有受热传播温度，GS 表面没有材质发射率。当前未模拟相机波段、烟气光谱、反射、镜头和探测器响应；热像遮挡仅来自 GS，不包含机器人网格。GS 深度的空洞和粗糙表面、仿真与 GS 的配准误差会直接影响热像边界。三处火源仍是独立仿真播放，不是全房间耦合热场。
