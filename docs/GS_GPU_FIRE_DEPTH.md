# GPU GS 深度逐帧接入火焰（2026-09-09）

已验收的实时深度与前序主界面改动先提交为 a77cbec。本轮改动位于该提交之后。

## 渲染路径

相机 beforePasses 中执行 GS Picker 深度通道，再绘制主场景与火焰。
同一帧主相机、相同设备分辨率，三个火点、V1/V2 和氛围直接采样同一 GPU 纹理。
GPU 按 IEEE754 big-endian RGBA 字节解码 normalized depth，转换到相机前向米制距离，
再除以视线前向分量得到体积射线终点。无效深度像素不作为实体遮挡。
原 FireProxyDepth 和窗帘范围豁免不再被运行时引用；文件保留供历史对照。

面板关闭时不调用纹理 read；开启时最多约 5 Hz 回读，缩至最多 640 宽用于面板，
不会降低火焰使用的 GPU 深度分辨率。场景卸载或上下文丢失会使旧深度失效。
关闭火焰遮挡且关闭氛围及面板时不绘制额外深度。暂停火焰时仍跟随相机更新遮挡。

## 检查

- 121 前端测试通过；TypeScript、Vite、Tauri release 和 NSIS 打包通过。
- scripts/verify-gs-gpu-fire.mjs：关闭面板约 0.7 秒生成 43 GPU 帧，纹理 read 调用为 0，CPU frame 为 null。
- 连续移动相机 30 帧，深度生成时记录的相机变换与主画面变换无不一致。
- 真实窗帘视角中，GS 深度小于 1.5 m 的前景区域且与火焰包围体相交的像素共 337930；
  关闭遮挡时有 31678 像素被火焰改变，开启后为 0（RGB 差异阈值 24）。这验证该区域，不能外推为整场景零漏火。
- 960×640 GPU 分辨率、第一视角、面板 640×427 并行预览、V2 切换及卸载清理通过；无浏览器错误。
- 三处多点回归约 60 FPS（RTX 4060 Laptop，1280×720，Edge WebGL2）。
- 已提交验收版本回测也出现桌面固定视角局部模糊，保存 accepted-baseline-rgb.png 供对照；未将其误判为本轮新增。
- 原 scripts/verify-gs-depth.mjs 通过，低频深度面板功能保留。

## 尚待人工验收

这是正确来源和时序的深度接入，不代表火焰与着火物的附着关系已经全部修正。
窗口透明边缘、单高斯 alpha 阈值形成的空洞仍可能漏火。窗帘体积埋在表面后方的部分会被裁掉，
顶部烟雾可能显露 GS 深度轮廓。此轮不重新引入范围豁免，也未改火焰位置或燃烧数据。
视口机器人网格不属于 GS-only 深度；需要遮挡火焰时应另行合并网格深度。
