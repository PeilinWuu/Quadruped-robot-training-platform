# GS 场景地面与台阶：调查和下一步方案

本轮完成矩形机器人占地判定，以及已有高度图索引修复。下面是地面/台阶方案，尚未实现台阶地面代理或足端 IK。

## 已确认的问题

1. `tools/robot_motion/build_ground_collision_proxy.py` 只读取源 Z 在 -0.12 至 +0.12 m 的点，再把结果夹在全局地面中值 ±0.08 m。这份数据用于主地面，不能表达更高的台阶。
2. 导出 NumPy 数组 shape=[119,86]（X/Y，C order），前端此前按 Y/X 索引。已对比源 NPY 和 public 二进制：public 与原 C order 完全一致，并非转置数据。本轮改为 ix * shape[1] + iy，新增非方形网格测试。
3. 如果存在三点地面标定，`GroundCollisionService.sample` 优先返回该平面，在整个查询空间覆盖原高度图。单个平面不能表达两级地面或台阶。
4. 高度查询只发生在机身中心；机身固定高于查询结果 0.30 m。腿部是程序化关节动画，没有四足地形采样、支撑期锁足或摆动期越障。
5. 站姿官方网格 AABB 相对根节点大致 X=[-0.378,0.332]、Z=[-0.162,0.162]、最低 Y≈-0.353 m。这提示根节点离地高度与脚底接触高度还需独立校准；AABB 最低点不是可靠的足端接触测量，不能直接拿差值全局抬高机器人。

## 建议的展示方案

采用“经确认的地面代理 + 台阶接触面 + 四足贴地”，与 GS 外观、空气墙障碍保持相同坐标变换。

- 主地面、抬高平台分别使用有边界的平面/多边形。
- 台阶用独立踏面和立面，或显式盒体。保留离散高度跳变，不把跨台阶采样平均成斜坡。
- 规则平台也可导出局部高度场，但不要继续使用全场单平面，也不要将家具顶面作为地面。
- 初始轮廓可由多个 GS 深度视角和语义结构辅助提取；边界、高度和低置信度区域需人工确认。最终运行使用稳定代理，不随当前展示相机或深度面板变化。
- 每只脚单独向下查询可落足表面。支撑期保持足端位置，摆动期生成抬脚轨迹；用两段腿的 IK 计算关节角，依据支撑足调整机身高度和有限倾斜。
- 由展示控制器限定允许迈上的高度、向下落差和过渡速度。越过能力之外的台阶应停止；这些参数只是展示约束，不代表机器人真实越障能力。

实现顺序：先做一个主地面与一个抬高平台/台阶的可视化标定样例；确认接触面后做站立四足贴地；最后接入行走跨级过渡。先验证局部区域再扩展全场。

## 验收标准

- 同一表面站立时四足不持续悬空或穿透。
- 前后脚处于不同踏面时，分别落在自己的踏面，机身不会突然整体跳高。
- 碰到高于允许迈步高度的立面时停止，后退正常。
- 改变观察相机、关闭深度/热像面板不改变脚下接触面。
- 图形和机器人标定旋转/缩放后，代理边界仍与 GS 对齐。
