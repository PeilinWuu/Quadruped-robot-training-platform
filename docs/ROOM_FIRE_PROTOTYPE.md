# 初步多点火场：桌子、沙发、窗帘

2026-09-08。人工验收认为 V1 优于 V2，因此暂停 V2 视觉改进。本轮保持 V1 的
颜色、烟雾和 96 步着色器不变，只增加多个独立火点的同时播放。

## 使用

桌面开发版中，点击视口上方「火焰播放」工具栏的 **启动多点火场**。
程序加载桌面 V1 和新增沙发/窗帘 V1 播片，统一重置并播放。
首次未加载桌面资产时也能直接点击这个按钮。

- 播放、暂停、重置同时控制三处火焰。
- 「看桌子 / 看沙发 / 看窗帘」使用已有原生相机书签；点击时退出第一视角，
  随后仍可继续旋转、平移、缩放。启动多点模式本身不会移动相机。
- 「切回单桌火焰」释放新增服务、体积网格和纹理，桌面播片保留当前播放状态。
- 多点模式固定使用 V1；要测试 V2，先切回单桌模式。
- 如果新增资产失败，显示错误，仍可使用已加载的桌面火焰。

当前本地服务通过 `/fire-playback-room/sofa_high/` 和
`/fire-playback-room/curtain_high/` 提供新增资产。

2026-09-08 起，`npm run tauri -- build` 会将桌面 V1、沙发/窗帘 V1 和已有
V2 原型的数据打入安装版，无需启动 Vite 或保留 D 盘播放数据。构建机器仍需
具备上述 D 盘源数据；普通 `npm run build` 不复制这些数据。
安装包输出在 `src-tauri/target/release/bundle/nsis/`，双击 setup.exe 安装，
再从开始菜单打开 Quadruped Robot Research。SOG 场景仍通过应用内导入，
本轮没有将物理仿真 sidecar 加入安装包。旧安装包不包含多点火场。

## 实现范围

复用 `production_regression/sofa_high/sim_output` 和
`production_regression/curtain_high/sim_output` 的现有数据，没有运行物理仿真。
两组独立场景保持原始世界坐标，不将桌面火焰复制到其他物体上。
新增导出工具：`FieryGS/adapter/fire_showcase/export_room_fire_playback.py`。
输出目录：`D:/interiorgs_data/office_01/fire_playback_room`。

| 火点 | 帧数 | 裁剪尺寸 | 播片字节 |
|---|---:|---|---:|
| 桌子 | 原有 72 | 43×43×71 | 原有资产未覆盖 |
| 沙发 | 16 | 22×88×67 | 4150784 |
| 窗帘 | 16 | 104×75×64 | 15974400 |

新增资产均为 V1 fuel+temperature RG8，4 帧一个 chunk；选择源帧
28,38,46,56,66,76,84,94,104,114,122,132,142,152,160,170。
FPS=1.690140845，使首末帧跨度与原桌面播片的 8.875 秒相同。
每个火点仍只保留相邻两帧和最多两个 chunk；三组共六张 RG8 GPU atlas。
所有体积共用透明层，并按当前相机方向排序。机器人、关节和键盘输入逻辑未改。
相机控制器只新增显式书签定位方法，鼠标输入规则未改。

这是**独立仿真播片的视觉叠加**，没有跨火点的温度、烟气、燃料或蔓延耦合。
仍沿用 V1 的遮挡限制：某些视角会透过前景物体看到远处火焰。未为本轮增加
GS 深度、场景炭化或全局烟雾计算。三个火点不代表整栋建筑的联合仿真结果。

## 验证

- RTX 4060 Laptop / Edge headless / ANGLE D3D11，1280×720，真实 SOG 与机器人运行时。
- 三处同时播放，分别观察桌子/沙发/窗帘，平均 60.1 / 60.2 / 60.3 FPS
  （每项约 3 秒，受刷新率限制；不是桌面 WebView 的长期性能验收）。
- 统一暂停与重置、第一视角切换、退出多点时服务与 GPU 体积清理通过。
- 浏览器控制台无错误。主界面启动/退出多点、查看按钮、V1/V2 切换通过。
- 主界面 1180/1440/1920 宽度以及滚动后，工具栏可见且可点击。
- 新增服务测试覆盖三轨联动、单资产失败、切换 V2 时清理多点状态。
- `npm test`：8 Node + 118 前端测试通过；`npm run build` 通过。
- 新增所有 chunk 的长度与 SHA256 验证通过。
