# Desktop-to-Go2手动验证

在普通试运行桌面检查通过之前，请勿启用 LIVE 模式。保留
官方管制员和第二名操作员在整个现场检查过程中做好准备。

## 试运行桌面

```bash
cd /data/Quadruped-robot-training-platform
source ~/unitree_ros2/setup.sh
npm run tauri dev
```

预期的用户界面状态：

- 网关已“就绪”，模式为“DRY-RUN”。
- 物理在线为“否”，因为试运行不订阅机器人数据。
- 安全确认无法解锁控制。
- 站立、躺下和定时移动被禁用。
- 关闭应用程序不会留下“go2_real_gateway.py”进程。

## 实时桌面

仅当机器人位于开放地板上且官方控制器准备就绪后：

```bash
cd /data/Quadruped-robot-training-platform
source ~/unitree_ros2/setup.sh
QUADRUPED_GO2_GATEWAY_LIVE=1 npm run tauri dev
```

UI 必须显示“LIVE”，但控件仍必须锁定。解锁之前，
验证最近的遥测将物理在线更改为“是”以及电池，
IMU、脚部受力、12个关节、Sport状态可见。

`SportModeState.error_code` 仅显示为原始十进制/十六进制字段。它是
供应商特定的位语义尚未得到验证，因此非零值是
已记录，但其本身并不声明故障或闸门运动。

验证顺序：

1. 按“停止移动”；观察三个 API 1003 请求。
2.检查现场安全确认及解锁控制。
3. 站起来，然后使用`vx=0.05`，其他速度为零，`duration=300 ms`。
4. 观察一个 API 1008，后跟三个 API 1003 请求。
5、开始两秒的移动，立即按STOP；运动必须提前结束。
6. 在有界低速移动期间断开遥测；网关必须发出
`move_stopped` 与 `telemetry_timeout` 并发送 StopMove。
7. 关闭应用程序之前锁定控件。

## 真机/仿真统一键盘控制

仅以低速继续，机器人站在空地中央
测试区。不要与桌面同时运行“go2_wasd_control.py”。

1. 启动 Go2 MuJoCo 仿真；保持 LIVE、最近遥测、站点确认和控制解锁处于活动状态。
2. 在仿真控制区点击唯一的 `启用同步键盘控制`，分别短按 W/S。仿真与
真机必须同时使用 0.30 m/s 指令向前/向后移动，并在释放后立即停止。
3. 短按 A/D 验证两端横移方向一致，再短按 Q/E 验证两端左/右偏航一致。
4. 按住 W 并添加 A，然后添加 Q。每个按键转换都应替换当前的按键转换
API 1008 意图，无需中间 StopMove；释放所有键停止。
5. 移动时，按空格键。运动必须停止，但键盘控制仍处于待命状态。
6. 再次移动，然后按 Esc。运动必须停止并且键盘控制被解除。
7. 重新装备、移动和更改应用程序焦点。窗口模糊必须发送 StopMove。
8. 重新启用并按住一个移动键三秒以上。机器人必须继续运动，直到松开
该按键；松开后必须立即发送 StopMove。
9. 保持一个运动键时制造短暂遥测空窗。当前运动不得被计时终止；松键
仍须发送 StopMove，遥测恢复前不得接受新的非零运动意图。
10. 锁定真机控制后继续使用同一个键盘按钮，按键必须只驱动仿真；重新
解锁真机后，同一键盘意图必须自动恢复双端扇出，不需要切换第二套键盘。
11. 依次持续按住 W、A、Q 各 10 秒。仿真模型应播放稳定的趋势动画，
坐标持续单调变化，不得跌倒、弹飞、出现求解器故障或停止响应；面板应显示
`go2-kinematic-animation-v1` 和“动力学求解 未启用”。
12. 分别按住 W、A 一秒：仿真局部前向、横向位移量应各约为 0.30 m；
按住 Q 一秒，仿真 yaw 应约增加 0.50 rad。键盘重复与 UI 刷新会带来少量
人工计时误差，但停止后坐标不得继续漂移。
13. 完成后发送 StopMove 并锁定控制。

在每一步中，显示的当前意图必须与按下的按键集相匹配。组合变化时立即
发送运动命令，保持期间以 250 ms 周期刷新高层 API 1008；这不是
`/cmd_vel` 或关节控制心跳。

仿真端在此模式下不计算足底受力、碰撞响应、关节力矩或 MPC。关节动作仅是
程序化的对角步态动画；`expectedContacts` 只是动画相位提示，不是物理接触
测量。真机端仍由 Unitree Sport 高层指令完成真实运动。

仅网关准备就绪永远不能算作机器人在线。新动议依然存在
每当物理遥测超过两秒时就会被阻止。

## 真机/仿真同步原点

此项校准坐标原点；运动同步由上面的统一键盘指令扇出完成。

1. 启动 MuJoCo，确认机器人面板出现 `统一坐标 · ROS Z-up`，且显示
   `world → odom → base_link`。
2. 保持仿真机器人静止，把真机放到希望对应的起点和朝向。
3. 等待真机在线并同时出现 Sport position 与 LowState IMU RPY。
4. 点击 `以当前仿真位姿设置同步原点`。
5. 确认同步状态显示 `已设置`，位置误差和 Yaw 误差接近零。
6. 真机向前短距离移动，确认真机 world X 主要变化；向左移动时 Y
   应增加，左转时 yaw 应增加。
7. 重置或重启真机里程计后必须清除并重新设置同步原点。

Sport position 当前标记为低置信度局部里程计。记录一次直行、横移、
旋转和返回起点后的 XYZ/yaw，用于确认轴向、复位行为与累计漂移。
