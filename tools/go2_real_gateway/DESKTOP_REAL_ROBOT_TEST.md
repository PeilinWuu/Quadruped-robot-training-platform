# Desktop-to-Go2手动验证

在普通试运行桌面检查通过之前，请勿启用 LIVE 模式。保留
官方管制员和第二名操作员在整个现场检查过程中做好准备。

## 试运行桌面

```bash
cd /data/Quadruped-robot-training-platform
source ~/unitree_ros2/setup.sh
npm run tauri dev
```

预期的用户界面状态：

- 网关已“就绪”，模式为“DRY-RUN”。
- 物理在线为“否”，因为试运行不订阅机器人数据。
- 安全确认无法解锁控制。
- 站立、躺下和定时移动被禁用。
- 关闭应用程序不会留下“go2_real_gateway.py”进程。

## 实时桌面

仅当机器人位于开放地板上且官方控制器准备就绪后：

```bash
cd /data/Quadruped-robot-training-platform
source ~/unitree_ros2/setup.sh
QUADRUPED_GO2_GATEWAY_LIVE=1 npm run tauri dev
```

UI 必须显示“LIVE”，但控件仍必须锁定。解锁之前，
验证最近的遥测将物理在线更改为“是”以及电池，
IMU、脚部受力、12个关节、Sport状态可见。

`SportModeState.error_code` 仅显示为原始十进制/十六进制字段。它是
供应商特定的位语义尚未得到验证，因此非零值是
已记录，但其本身并不声明故障或闸门运动。

验证顺序：

1. 按“停止移动”；观察三个 API 1003 请求。
2.检查现场安全确认及解锁控制。
3. 站起来，然后使用`vx=0.05`，其他速度为零，`duration=300 ms`。
4. 观察一个 API 1008，后跟三个 API 1003 请求。
5、开始两秒的移动，立即按STOP；运动必须提前结束。
6. 在有界低速移动期间断开遥测；网关必须发出
`move_stopped` 与 `telemetry_timeout` 并发送 StopMove。
7. 关闭应用程序之前锁定控件。

## 真正的键盘控制

仅以低速继续，机器人站在空地中央
测试区。不要与桌面同时运行“go2_wasd_control.py”。

1. 保持 LIVE、最近遥测、站点确认和控制解锁处于活动状态。
2. 点击 `启用真机键盘`，分别短按 W/S。机器人必须使用原脚本的
0.30 m/s 指令向前/向后移动，并在释放后立即停止。
3. 一次点击 A/D 进行横向移动，然后点击 Q/E 进行左/右偏航。
4. 按住 W 并添加 A，然后添加 Q。每个按键转换都应替换当前的按键转换
API 1008 意图，无需中间 StopMove；释放所有键停止。
5. 移动时，按空格键。运动必须停止，但键盘控制仍处于待命状态。
6. 再次移动，然后按 Esc。运动必须停止并且键盘控制被解除。
7. 重新装备、移动和更改应用程序焦点。窗口模糊必须发送 StopMove。
8. 重新启用并按住一个移动键三秒以上。机器人必须继续运动，直到松开
该按键；松开后必须立即发送 StopMove。
9. 保持一个运动键时制造短暂遥测空窗。当前运动不得被计时终止；松键
仍须发送 StopMove，遥测恢复前不得接受新的非零运动意图。
10. 启用模拟键盘控制。真正的键盘控制必须解除并
发送停止移动。切换回真实键盘必须解除模拟输入。
11. 完成后发送 StopMove 并锁定控制。

在每一步中，显示的当前意图必须与按下的按键集相匹配。组合变化时立即
发送运动命令，保持期间以 250 ms 周期刷新高层 API 1008；这不是
`/cmd_vel` 或关节控制心跳。

仅网关准备就绪永远不能算作机器人在线。新动议依然存在
每当物理遥测超过两秒时就会被阻止。
